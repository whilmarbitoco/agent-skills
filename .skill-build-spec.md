# Skill Build Specification
# All subagents MUST follow this exactly.

## Directory layout (each skill)
```
<domain>/<skill-id>/
├── SKILL.md                 — under 35 lines. name, description, concepts, rules, anti-patterns, related.
├── anti-patterns.md         — real Java code showing WRONG way + fix explanation. 3-5 patterns. 40-90 lines.
├── checklist.md             — 2 sections: Implementation + Review. Short bullets.
├── examples/
│   └── <name>.java          — real compilable Java 21 code. At least 1 file.
└── references/
    └── quick-reference.md   — API table, < 15 lines.
```

## SKILL.md frontmatter (required)
```yaml
---
name: <kebab-case-id>
description: >
  Starts with action verb. Extends agent's knowledge of X. Use when Y.
compatibility: Java 21+
metadata:
  domain: <domain-name>
  level: beginner | intermediate | advanced
  stack: [java-21, ...]
  version: "1.0.0"
---
```

## Java code rules
- Java 21 features: records, sealed classes, pattern matching, virtual threads
- Stack: Java 21, JavaFX 21, Maven 3.9+, Ebean 15, SQLite 3.45+, SLF4J 2.x
- Money: `BigDecimal` + `Currency.getInstance("PHP")` — never double/float for amounts
- Constructor injection only. No static mutable state. No @patch/MagicMock.
- SLF4J parameterized logging (`log.info("Saved {}", id)` not string concat)
- Records for value objects, Ebean entities stay as classes

## Quality bar
- SKILL.md: action-oriented, specific rules, no "use when..." filler
- anti-patterns.md: minimum 3 real code examples with `// WRONG` and `// FIX:` comments
- examples/: minimum 1 .java file with working code
- checklist.md: under 10 bullets total

## What NOT to do
- No walls of markdown explanation
- No generic advice ("write clean code", "follow best practices")
- No stub files with placeholder text
- No identity/Hermes/Ciel agent-specific content
